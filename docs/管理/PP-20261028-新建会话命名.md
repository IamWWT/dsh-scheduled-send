# 新建会话被任务标题命名（0.10.7）

目标：在工作区里点「新会话」得到的会话不带任何定时任务标题，也不会变成某个任务的投递会话。

## 现象（用户报告，生产 3082）

「虽然周期性定时任务不在对话框显示了，但是在对应对话框新创建对话时，每次 session name 自动被创建成『月报-月报总结』」。
截图要点：左侧工作区列表出现一项任务标题（时钟/刚刚），其下会话名同样是该任务标题。

## 根因（2026-10-28 取证）

不是 dsh-notify-alert：该插件只读 `title` 投影（`src/host/session-label.ts`），源码里没有
`sessionController` / `rename(` 调用。

真实链路在宿主 web 的「新会话」：

1. 插件 `resolveTarget` 用 `sessionController.create({workspaceId})` 新建任务会话并立即
   `rename()` 成任务标题（`src/host/bridge.ts:542-551`）。
2. 该会话**没有 `turn/start`** ⇒ 宿主认定为「空白会话」（`packages/api/session-controller/src/list.ts:51`；
   `agent.ts:399` `reuseLive` 只判 `isBlank`）。
3. web「新会话」会把该工作区**列表里的第一个空白会话**交给 `session.create` 复用
   （`packages/client/ui-workspace/src/client/navigation.ts:243` `createInWorkspace`）。
4. 于是用户的新会话 = 任务会话，标题已被 rename 钉死 ⇒ 名字变成任务标题；下一次任务投递还会落进用户的对话。

隔离实证：修复前 `session/create` 请求体带 `"sessionId":"session-b9f6a39a-…"`（正是任务会话）。

## 方案

不改上游、不清空宿主内部空白状态。插件建完会话后立刻用公开 `workspace.detachSession` 让它退出工作区
成员席位：既不出现在工作区列表，也不满足复用条件（复用要求 `workspace.sessionIds.includes(id)`）。

- 首次真实投递（官方 schedule framing，`bridge.ts` `onSessionEvent`）或「立即执行」后
  `attachSession` 挂回工作区 —— 此时会话已有真实轮次，不可能被复用，用户仍能点开看历史。
- 启动时一次性迁移：只摘「插件建过（meta 有 sessionTitle）且从未投递过」的旧空白任务会话，
  因为宿主 bootstrap 会按 cwd 把它们重新挂回工作区。

## 验收

- `pnpm check` 全绿（smoke 新增 3 段断言：建会话即退席、投递后挂回、启动迁移只摘未投递的）。
- 隔离 home（`ops/validation/notify-naming-20261028`，127.0.0.1:3086，pnpm 用仓内 store）装 0.10.7：
  - 建任务后 `workspace.json` 的 `sessionIds` 为空（任务会话不在名单），会话日志仍是
    「标题 + 无 turn/start」。
  - 浏览器点「新会话」：`session/create` 请求体只有 `workspaceId`，不带任务会话 id；侧栏显示
    `工作区 / demo-ws / 新会话`，不再出现任务标题行。
  - 手工把任务会话写回名单模拟宿主 bootstrap 重启：0.10.7 启动把它再次摘掉，用户自己的空白会话保留。
  - 「立即执行」后任务会话重新出现在名单（挂回）。
  - 任务页「打开会话」对已退席会话仍能打开（空白时落在「未分组 / 新会话」，是宿主既有表现）。

## 未验证 / 剩余

- Windows 桌面版、真实手机 WebView 未实测（宿主 web 端复用逻辑两端口径一致，但未跑）。
- 生产 `~/.dsh-dev` 未安装 0.10.7（需用户同意后重启 `dsh-dev-web`）；生产现有 4 个空白任务会话
  要等这次升级的启动迁移才会退席。
- 隔离环境用 `pnpm install --store-dir <仓内 store>` 装 tgz：`dsh plugin add` 在本会话沙箱里因
  pnpm 默认 store（`~/.local/share/pnpm/store`）只读而失败（EROFS），无法在本会话提权。

回滚：把 profile 依赖改回上一版 tgz 重装重启；0.10.7 只改工作区成员席位，不写会话日志、
不改官方 schedule 数据，回滚后任务会话照旧在名单里。
