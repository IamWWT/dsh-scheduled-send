# 每次执行新建会话（0.10.8 per-run 轮转）

目标：日报/周报这类采集任务**每天一个新会话**，历史各在自己的会话里，不需要事后重绑。

## 需求（用户原话）

> 「日报-每日日记收集 任务会话 为什么会要绑定会话? 每天后续都有这个收集动作, 难道都要重新绑定?」

0.10.7 解决了「新建会话被命名成任务名」，但任务的投递目标仍是一个固定 `sessionId`
（官方 Schedule 的任务行就是这么设计的）。用户要的是**任务自己每天换会话**，且默认只对采集类任务生效。

## 官方契约核对（决定实现方式）

- `ScheduleCatalogEntry` / `list` 都按 `sessionId` 投递；任务行的 `sessionId` 是**绑定**。
- `update(request)` 的公开面只有 `title` / `prompt` / `change`（时间规则），
  `sessionId` 只作为**身份校验**（`ScheduleUpdateRequest`，`packages/schedule/schedule/src/types.ts:424`，
  实现见 `schedule/src/update.ts`）——**没有「改绑定」的公开面**。
- 因此「重指会话」只能等价为**删旧建新**：`create(newSessionId, 同一份 title/prompt/规则)` 然后 `delete(旧)`。
- 投递提交后官方会 `emitChanged()`（`schedule/src/index.ts` 的 runtime commit 回调），
  插件监听 `schedule/changed` 即可在**页面关闭时**也观察到投递，不依赖 UI 轮询。

## 轮转语义

1. 判据：任务 `active` + 周期频率（`every/daily/weekly/cron`）+ `meta.sessionMode='per-run'`
   + 官方 `lastDelivery.messageId` ≠ `meta.rotatedFrom`（**幂等键**）。
   一次性任务（`once/after`）投递后就 `inactive`，不轮转。
2. 顺序：建新会话 → `rename` 成 `${任务名} · <本地日期时间>` → **立即退席**（沿用 0.10.7）→
   应用模型 → 打 `pendingSwap` 标记 → `create` 新官方任务 → `delete` 旧官方任务。
   **先建后删**：任何一步失败都不会让任务消失。
3. 删旧失败 → 删掉刚建的新任务（回滚），任务回到原会话，写 `rotateError`。
4. 进程在「建新 → 删旧」之间退出 → 下次刷新按 `pendingSwap` 收尾（删旧留新），
   同一条提示词不会投两次。
5. 失败：保留原任务继续按原会话、原周期执行；同一次投递最多重试 **2** 次
   （刷新很频繁——UI 5s 轮询 + `schedule/changed`，无上限会每 5 秒重建一次会话）；
   错误写进 `rotateError`，页面显示。

## 会话可见性

- 新会话建好即退席 → 不会被 web「新会话」复用（0.10.7 的根因）。
- 会话出现 `turn/start` 后挂回工作区 → 用户能在侧栏按天点开历史。
  `runSessionIds` 保留最近 20 次执行会话，避免两次投递挨得很近时前一个会话永远挂不回去。
- 未执行的新会话保持退席。

## 已知取舍（必须让用户知道）

- **官方投递历史会随旧任务行一起清空**：轮转 = 删旧建新，`history()` 对新任务是空。
  插件改在 meta 里记 `lastRunSessionId` / `runSessionIds`，历史本体在会话日志里。
- **`every` 的锚点会随轮转重置**：新任务的下一跳 = 轮转时刻 + 间隔（偏差 = 轮转耗时，几十毫秒）。
  `daily/weekly/cron` 按本地钟表时间重算，无漂移。
- **删旧 → 建新之间有毫秒级空窗**：已投递后官方把 `scheduledAt` 推到下一跳，空窗内不会到期。
- 轮转瞬间任务 id 会变（官方分配）：页面用旧 id 点编辑/删除/立即执行时按内存映射跟随到新任务
  （不跨重启；重启后页面刷新即可）。

## 验收

- `pnpm check` 全绿：新增 `test/per-run-rotation-test.mjs`（模式缺省、轮转、幂等、失败保留/回滚、
  半截交换自愈、执行过的会话挂回），既有 smoke/routes/opener/meta/hooks/archive 全过。
- 隔离实例真跑（`ops/validation/sched-per-run-20261028`，127.0.0.1:3088，独立 home）：
  `every 60s` 的 per-run 任务连跑两轮 → 两个不同会话各 1 次投递、任务指向第三个未使用的会话；
  fixed 任务两轮都进同一会话。证据与复跑命令见该目录 `README.md`。
  （官方固定间隔最小 60 秒，无法用 10 秒间隔复现。）
- 顺带修掉并发竞态：`MetaStore.reconcile` 只删「快照取样时刻之前就不在官方表里」的元数据。
  否则 `bridge.start()` 的非阻塞刷新会把紧接着 `create()` 写入的 `builtin/sessionMode` 抹掉。
