## 1. 入口排序锚点 = Vision Router（order 12，v0.2.0 需求）

被删原文（README.md §当前能力清单 · 任务管理，2026-10-13 前）：

```
- 设置 → 左侧「定时发送」（`settings.section`，order 11，在 Vision Router 的 12 左边）：按**待触发 / 已发送 / 失败 / 已撤回**分组，完成态默认折叠，点分组标题展开。
```

被删原文（AGENTS.md §本插件专属硬规则，2026-10-13 前）：

```
- **入口插槽**：主入口 `conversation.input.right`（输入框 ⏰ 定时）；管理面板 `settings.section`（order 11，
  Vision Router 在 12，保证在其左边）。
```

删除原因：该括注把「Vision Router（上游 `dsh-vision-router`）已装且占 order 12」当作现状事实。

该插件未装于本机 web profile，故"在其左边"不再是可核对的现状描述。

现行口径：`settings.section` 的 order **11** 是插件的实际注册值（`src/client/entry.ts`）；

## 2. 浏览器需支持 `datetime-local`（v0.2.0–v0.4.x 的时间选择形态）

被删原文（README.md §环境支持矩阵 · 兼容基线，2026-10-13 前）：

```
浏览器需支持 ES2022 / `fetch` / `AbortController` / `datetime-local`
```

删除原因：`datetime-local` 是 v0.2.0–v0.4.x「快捷时长（15m…20h）+ 自定义 `datetime-local`」时代
的时间选择控件；现行 UI 是**三段 `时 : 分 : 秒` 下拉**（`src/client/ui.ts` 的 `ClockPicker`，
`0–23 / 0–59 / 0–59`）+ 今天/明天档位，源码中已无 `datetime-local`（全仓 `grep datetime` 无命中）。

现行口径：[../需求/BRD-业务需求说明书.md](../需求/BRD-业务需求说明书.md) §2.1 / §2.2。
该形态的历史口径（含 `MAX_SCHEDULE_HOURS = 20`、"今天已过自动顺延"）同样记在该文件 §2.2，
以及 [../管理/RMP-风险管理.md](../管理/RMP-风险管理.md) 的「2026-09-10 v0.2.0 需求迭代」条。

## 3. 会话元数据经 `useSessions` 投影取用（v0.6.1–v0.7.0 的写法）

被改写原文（README.md §当前能力清单 · 任务管理，2026-10-13 前）：

```
- 每行展示完整 sessionId + 会话标题（displayTitle）+ 工作目录 cwd（数据源 = dsh `useSessions` 投影，实时权威）；
```

被改写原因：组件内**禁止条件调用 hook**（v0.7.1 的 #310 根因修复）之后，本插件不再消费
`useSessions` hook——`src/client/ui.ts` 只保留 `useSessions?:` 的**类型声明**，无任何调用点；
会话元数据改由 `src/client/entry.ts` 在注册层经 `sessions.list.getSnapshot()` 取**同步快照**，
交 `src/shared/session-meta.ts` 折叠为 `sessionId -> {title, cwd}` 传入。

现行口径：[../需求/BRD-业务需求说明书.md](../需求/BRD-业务需求说明书.md) §1 表下注与 §2.6；
实现见 `src/client/entry.ts`（`sessionMetaOf(svc.list.getSnapshot())`）。
历史故障链（条件 hook → #310）见 [../管理/RMP-风险管理.md](../管理/RMP-风险管理.md) 与 `CHANGELOG.md`
的 v0.7.1 / v0.7.2 两条（未改动）。

## 4. 配置写在 `$DSH_HOME/settings.yaml`（0.1.7 前的配置入口）

被删原文（README.md §边界，2026-10-13 前）：

```
- 配置只声明代码实际消费的键：`scheduled-send.stateDir`（留空 = `$DSH_HOME/profiles/web/scheduled-send`），写在 `$DSH_HOME/settings.yaml`。
```

删除原因：框架不再加载 `$DSH_HOME/settings.yaml`——迁移时把它改名为 `settings.yaml.imported`，
只对能映射到条目 id 的段生效（`dsh-plugins/docs/管理/CMP-插件开发规范.md` §2.7.1；
本机 2026-10-13 实测 `~/.dsh-dev/` 下只有 `settings.yaml.imported`，无 `settings.yaml`）。

现行口径：配置键 `stateDir` 的声明处是插件自带 `cordis.patch.yml` 的 bundle insert config（缺省 `""`）；
本插件**未注册**设置面板配置卡片，覆盖走 profile 侧配置。见 [README.md](../../README.md) §边界。

## 5. 纯文本边界引用 `dsh session-prompt` 兜底通道（失效引用）

被删原文（README.md §边界，2026-10-13 前）：

```
- 不处理图片 / 附件（纯文本，与 dsh `session-prompt` 兜底通道一致）；不做跨设备 / 多 profile 同步（MVP 只覆盖当前 web profile）；不修改 dsh 排队 / Inbox 机制本身。
```

删除原因：`session-prompt` **不是上游 dsh（deepseek-harness）的机制名**——在
`deepseek-harness/`（0.2.1-alpha.2 源码，含 packages/apps/docs）中检索不到该名；
本机实装的 `dsh-daily-workbench` 确有一个同名 HTTP 端点 `POST /session-prompt`，
但那是插件自建通道，不是"dsh 兜底通道"，故不再作为本插件的边界依据。

现行口径：边界判据回到本插件代码本身——`src/host/scheduler.ts` 的 `fire()` 只投
`content: [{ type: "text", text }]`，无图片 / 附件路径。
